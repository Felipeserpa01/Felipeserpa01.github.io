case 01

Validação de notas fiscais de colaboradores PJ

Ferramenta interna para RH · 2026
● em uso

Contexto

Boa parte dos colaboradores da empresa trabalhava como PJ e emitia nota fiscal todo mês. O RH precisava conferir cada nota antes do pagamento.

Problema

A conferência era feita nota a nota, à mão: valor, CNPJ, dados do tomador. Um trabalho repetitivo, demorado e fácil de errar.

O que eu fiz

Desenvolvi um sistema que lê as notas, valida os campos contra as regras definidas pelo RH e aponta divergências. Antes de escrever código, documentei o projeto em um brief estruturado, o que acelerou o desenvolvimento assistido por IA.

Resultado

O sistema entrou em uso e gera um relatório mensal de conferência das notas PJ. O RH passou a revisar só as exceções, não o lote inteiro.

PythonProcessamento de documentosRelatórios
case 02

Pipeline de dados financeiros

Ferramenta interna para o financeiro · 2026
pipeline de dados

Contexto

Os dados financeiros da empresa ficavam dentro do Omie, a plataforma de gestão contábil, sem uma forma simples de cruzá-los e analisá-los.

Problema

Qualquer análise exigia exportar planilhas manualmente e juntar tudo à mão, o que deixava a informação lenta e pouco confiável.

O que eu fiz

Montei um pipeline que extrai os dados pela API do Omie, armazena em PostgreSQL e disponibiliza um painel em Streamlit. Tudo roda em containers Docker para facilitar implantação e manutenção.

Resultado

Os dados financeiros ficaram centralizados em um banco próprio, prontos para consulta e visualização, sem depender de exportações manuais.

PythonPostgreSQLStreamlitDockerREST API
case 03

Servidor WebSocket em tempo real

Desafio técnico de backend · 2025
tempo real

Desafio

Construir um servidor que aceitasse vários clientes conectados ao mesmo tempo, enviasse dados em tempo real e mantivesse o estado dos usuários sempre atualizado no banco.

O que eu fiz

Implementei com FastAPI um servidor WebSocket assíncrono que transmite a data e hora a cada segundo para todos os clientes e calcula números de Fibonacci sob demanda. Cada conexão e desconexão atualiza a tabela de usuários conectados no PostgreSQL.

Infraestrutura

Servidor e banco sobem juntos com Docker Compose, incluindo o script de criação do schema. Basta um comando para rodar o projeto em qualquer máquina.

O que aprendi

Programação assíncrona com asyncio, gerenciamento de múltiplas conexões persistentes e broadcast de mensagens sem bloquear o servidor.

PythonFastAPIWebSocketsasyncioPostgreSQLDocker Compose

case 08

Produto tensorial com multithreading

Projeto acadêmico · Programação concorrente · 2024
concorrência

Desafio

Calcular o produto tensorial (Kronecker) de duas matrizes, uma operação cujo resultado cresce muito rápido com o tamanho da entrada.

O que eu fiz

Dividi o cálculo entre várias threads POSIX, cada uma responsável por uma faixa de linhas do resultado, para aproveitar os núcleos do processador. A saída é comparada com um gabarito para validar a corretude.
